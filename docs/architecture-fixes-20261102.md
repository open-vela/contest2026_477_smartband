## 运动页冻结根因

保留的异常记录显示 UI 任务在 FreeType 字形缓存查找时发生 data abort。真板启用的 G2D 填色代码把目标格式固定为枚举值 0，即 ARGB8888，而 LCD 缓冲区为 RGB565：按两字节计算的像素 pitch 被硬件按四字节执行，覆盖缓冲区后面的堆内存，最终使字形缓存指针损坏。

有界 DMA 模型直接编译原填色函数并复现越界，改为 `g2d_get_px_format(dest_cf)` 后通过。同一处格式修改单独上板后，原来稳定冻结的 START 流程成功完成。随后修复图片路径的屏幕坐标/缓冲坐标混用、带 padding 的 pitch、缓存维护范围，以及把文件名或 layer 当作图片头读取的错误。保留支持场景的 G2D 加速，无法表示的行跨度交给软件绘图。

异常和对照测试分别保存在 `sport-panic-summary.json`、`g2d-format-regression.json`、`g2d-buffer-regression.json`；完整 dmesg 只保存在本机私有工作目录。

## LCD 数据

初版每块 4096 像素即 8192 字节，超过 R528 HAL 的 4160 字节中转缓冲。更大传输要求指针和长度均按 64 字节对齐，任意脏矩形未满足，导致 DMA 配置拒绝和后续 SPI 超时。失败样本保留。

修复为每块最多 **2048 像素 / 4096 字节**，底层在启动 SPI 前检查容量。320×120 紧密矩形只需 11 个命令/参数写入和 19 个像素块。最新代码另将转换缓冲从 153600 字节降为 4160 字节，释放 **149440 字节（145.94 KiB）**。

| 猫咪场景 | 旧逐行路径 | DMA 分块修复版 |
|---|---:|---:|
| visual FPS | 60.00 | 59.94 |
| render 均值 | 8.857 ms | 5.455 ms |
| PUTAREA 均值 | 6.680 ms | 3.325 ms |
| 新增 ioctl 错误 | 0 | 0 |
| 漏过节拍 | 0 | 0 |

PUTAREA 均值下降约 **50.2%**。该对照样本窗口 10.01 秒，日志未见 SPI 对齐拒绝或超时。指标来自板端软件计数。

运动入口旧版实测 render 2.0 FPS，源码每 500 ms 跳变一次。新插值跟随显示节拍，小幅浮动的相同整数像素位置会合并，避免无变化重绘。
