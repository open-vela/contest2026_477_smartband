# 六动作优化及后台更新实机记录

日期：2026-11-02。设备：Gemini S1 / R528，单一 Native LVGL 显示入口。

## 结果

六种猫咪动作都达到约 60 次实际像素变化/秒。下表每项为约 20 秒独立窗口，切换与截图之后预热 5 秒，截图在采样窗口外。旧版为 2026-09-09 candidate08，新版为 2026-11-02 08:39:34 构建。全部窗口新增 decode/LCD ioctl 错误均为 0。

|---|---:|---:|---:|---:|
| 捂鼻摆手 | 56.90 | 60.00 | 60.50 | 16 / 2 |
| 害羞挥手 | 56.95 | 59.99 | 60.09 | 14 / 1 |
| 躺平刷手机 | 57.00 | 60.02 | 60.07 | 2 / 2 |
| 气球升空 | 32.85 | 60.05 | 60.00 | 0 / 0 |
| 仰头大笑 | 36.90 | 60.00 | 60.00 | 0 / 0 |
| 马桶摸鱼 | 56.95 | 60.00 | 60.75 | 6 / 2 |

`visual` 来自像素合成后确有变化才增加的计数；`motion` 是调度次数；`render` 是 LVGL 刷新次数，可能包含时钟等 UI 更新。计数器逐项读取且以板端 uptime 计时，窗口边缘可有小幅误差，60.05 不代表目标频率超过 60 Hz。这些是设备软件计数，不是光学屏幕帧率，也不能据此声称每一帧都恰好 16.67 ms。表中保留迟到/漏拍计数。

## 改动

- 将长时间重复的同一路径视为一个完整插值区间，修复气球/大笑长时间停帧、仅最后一个重复槽做插值的问题。原周期和区间边界不变，长帧视觉行为由保持后过渡变为持续交叉淡化。
- 缓存当前动作已经缩放和预乘的帧；64 项、2 MiB 上限，动作变化或销毁时释放，分配失败回退到原路径。
- ARGB8888 用两个独立 16 位通道组计算混合，保持原舍入结果和实际行 stride；16,777,216 组像素组合与逐通道基准逐项一致。
- 按动作起点的绝对 60 Hz 时间网格计算下一次回调，跳过已错过的时间点，消除相对 16/17 ms 定时器逐帧累积迟到。第一轮缓存/插值版为 56.45–56.87 visual FPS，最终调度版见上表。

## 页面切换的边界

重复横向滑动窗口：第一轮 render 46.78 FPS，最终调度版 render 49.15 FPS；最终平均 refresh 13.54 ms，LCD ioctl 新增错误 0。
该 20 秒窗口包含手势、滚动与停顿，不能解释为纯转场帧率。页面大面积刷新仍会挤占猫咪动画预算；健康、运动等各类内部动画尚未逐项完成性能剖析。因此本记录支持“六种猫咪动作约 60 FPS”，不支持“全部页面及所有动画均为 60 FPS”。

## 后台更新与数据

OpenixCLI 0.2.4 已连续完成两次无前台窗口更新。第二次由 `scripts/gemini_update.py` 一次调用完成：审查镜像、停写备份、RTC FEL、FES 写入与校验、ADB 回连、文件恢复和重启。318 个备份文件回读逐字节一致，见 `background-update-result.json`。

工具的 partition 模式仍处理 MBR 和启动区。本板实测升级后原 `/data` 文件不见，不能直接认为该模式保留文件系统；完整恢复已经执行并核对。私有备份没有放入本证据目录。使用方式见 [后台更新说明](../../gemini-background-update.md)。

固件包 71,931,904 字节、系统载荷 7,716,352 字节。与原 candidate08 相比只有 nsh/Vnsh 变化，其余 20 项逐字节一致。hushen 复用现有 build05/pack08，无新建远端源码树或候选版本目录。
